The complete runtime at `aca7c3fd01048f424f69286dbc938e87b1635561` passed the
[four-platform run](https://github.com/ramonruanxc/delphi-fiber-runtime/actions/runs/34552183646).

The following short shared-runner scenario plans 200 activations of one service
at a 1,000 us period, with one 64-byte event per activation, queue capacity 256,
one subscriber and 25 us event handler work. It uses a 10 ms warmup. This is
descriptive evidence; background load and power policy are uncontrolled.

Always read skips and intervals alongside lateness: skip-latest selects a recent
deadline, so a small lateness percentile alone can conceal missed periods.
These observations certify neither a universal 1 ms cadence nor an OS ranking.

The CI artifacts retain every raw sample and all 24 comparison reports. References

report, so counts are not presented as a controlled speedup ranking.

Independent review closed resume-admission, posted-payload rollback, active
delivery accounting, actual native joins and contradictory trace-validation
findings. Original reproducers passed after fixes. The final native regression
matrix covered Windows x86/x64 and WSL Linux x64; additional native-producer races
verified managed payload release and suppression of callbacks after service stop.

Physical machine suspend/resume, other FPC RTL versions and Delphi contexts remain
unqualified. The installed Delphi edition refuses CLI compilation; both compiler
probes recorded that result without treating exit code zero as a successful build.
The periodic core has its own compiler probe and does not require contexts.

Allocation entry calls, heap observations and sampled RSS/VMS have different
meanings. Later observer output additionally identifies sampled Windows private
commit and explicitly unavailable reservation/other-platform commit measurements.
No memory category is inferred from a different category. Tag builds regenerate
all evidence and binary hashes from the exact release revision.
